# Fixed Use-Case Examples

These examples show how selected standalone skills can improve a specific decision. They are fixed illustrations, not a dynamic method router.

| Example | Decision problem | Methods |
|---|---|---|
| [01](01-clarify-an-ambiguous-problem.md) | Turn mixed claims into a decision-ready problem | Evidence Map, Issue Tree |
| [02](02-diagnose-a-recurring-problem.md) | Diagnose an issue that returns after repeated fixes | Change Event Timeline, Systems Thinking, Constraint Analysis |
| [03](03-prioritize-options.md) | Compare options with explicit tradeoffs | Decision Matrix, Risk Matrix |
| [04](04-build-a-stakeholder-strategy.md) | Win support in a complex power structure | Stakeholder Power Map, Account Plan |
| [05](05-improve-product-adoption-and-roi.md) | Improve adoption and value realization | Evidence Map, Jobs To Be Done, Metrics Tree |
| [06](06-assess-a-market-entry.md) | Assess a market-entry decision | PESTEL, Porter Five Forces, Competitive Positioning |
| [07](07-career-change-baseline-vs-method-chain.md) | Compare a direct career-change answer with a four-skill reasoning chain | Evidence Map, Stakeholder Power Map, Scenario Planning, Weighted Scorecard |

Each example records:

- the input and evidence boundary;
- why each method changes the decision;
- the intermediate output;
- the effect on the next step;
- methods deliberately not used;
- the final decision artifact.

Example 07 adds a controlled comparison: the same input receives a direct answer with no named method and a second answer using a selected method chain. It shows whether the additional structure changes evidence discipline, stakeholder judgment, scenario robustness, prioritization, or decision gates.
